## 二、赛道适配：要补一个说法

赛道 04 的官方描述是“供其他应用采用的信任、身份、数据原语；不能只凭 AI 功能就把消费应用归到本赛道”。

TimeBank 现在看起来像一个消费 App。要让评委认它是 04，Pitch 和 README 要讲清楚：**底层是一个任何应用都能读、都能用的“双人在场凭证”原语**。

- 合约是公开的：任何护理机构系统、保险方、别的时间银行都能直接读 `Sealed`、`Arrived`、`VisitClosed` 事件，验证“谁、在谁家、待了多久、双方都签了”。
- TimeBank 的界面只是这个原语的第一个参考客户端。
- 点名的能力正好对上：P256 / WebAuthn（passkey 原生账户，没有助记词）。

## 四、创新点（技术上真正新的地方）

1. **双方本人当面签名，链上验证。** 被帮的人和帮忙的人各用自己的 Face ID 签同一条记录，合约用 Monad 的 P256 预编译当场验证两个 WebAuthn 签名。一次盖印 307,241 gas，端到端 1.7 秒（实测，`scripts/smoke.js`）。
2. **完全没有钱包。** passkey 就是身份，合约从签名本身恢复是谁签的，不存凭证 id；中转服务代付 gas 但没有任何权力，没有有效签名它什么也做不了。
3. **上门全过程，而不只是一次打卡。** 到门刷脸开始，双人盖印结束；合约记录实际在场分钟数，申报超过在场时标记核查；同一人同一时间只能有一个进行中的上门。
4. **盲化到门记录。** 链上只写 keccak(家人卡秘密, 随机数)，家人能认出自家门口的记录，外人对不上，不会泄露“独居老人此刻家里有没有人”。
5. **开门验真。** 老人开门前出示二维码，来人用 passkey 签名，一秒内显示“已验证，某社区志愿者”，冒充者签不出来。

## 五、差异化

| 现有方案 | 它证明了什么 | 我们多证明了什么 |
|---|---|---|
| 美国 EVV、韩国 RFID 标签、英国电话打卡 | 护工那一方到过（标签能被拆走，打卡能多地同时） | 被服务的人本人也当场确认；人搬不走 |
| 政府和机构的时间银行平台 | 机构录入的时长 | 双方本人签名；机构关了记录还在；跨城都能读 |
| 已有的“区块链 + 时间银行”试点 | 多用联盟链，机构单方上链 | 公共链、本人持有、双人签名、不需要钱包 |
| 普通的双签数据库 | 只要有一个各方都信任的运营方就够了 | 适合**多方互不信任**的情况：机构、保险、家属、不同城市 |

最后一行要在 Pitch 里如实说：如果只有一家机构和一家保险，普通数据库也行。链的价值在“没有一方被所有人信任”的时候。

## 六、商业潜力

- **谁付钱**：居家护理机构（自证、应对审计和追款）；长护险经办方、保险公司、Medicaid 项目（减少虚报）；社区和基金会（时间银行后台，低价）。个人永远免费，不发币，时间不能买卖。
- **为什么现在**：美国《21 世纪治愈法案》§12006 强制 Medicaid 居家护理做电子上门核验；各国核验都有公开的造假案例；passkey 已普及；AI 换脸让“来的是不是本人”更难判断。
- **护城河**：认可这份凭证的机构越多越值钱；社区背书网络靠运营积累。代码可以被抄，这一点要坦白。
- **怎么开始**：先找私营护理机构和已有的时间银行网络，不先碰政府，政府销售周期太长。
- **最大的风险**：没有验证过的付费意愿；健康数据合规（商业版链上只存哈希）；防不了护工和老人合谋，只能让抽查变便宜。
