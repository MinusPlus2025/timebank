# 反思：产品的漏洞、夸大之处和改进方向（2026-10-10）

> 用户要求"继续优化和反思，不要着急完成"。这里只记录分析和建议，尚未改代码。

## 1. 我们说过的话里，有哪些是夸大的
| 说法 | 实际情况 |
|---|---|
| "两个人刷脸，谁也造不了假" | 只能防**单方**造假（护工一个人、机构一个人、凭空捏造）。防不了**合谋**：护工和老人商量好，"你签个字，钱分你一半"。韩国研究和上海案件都显示受助方也会参与 |
| "证明这次服务真实发生了" | 现在的流程**不能证明两人在一起**。被帮的人可以在家签名，把二维码拍照发给对方，对方在另一个城市也能确认 |
| "家人代确认" | 家人不在现场，确认的只是志愿者的说法，本质是担保，不是证明 |
| "链上公开，更可信" | 公开也带来隐私风险，见第 2 节 |

## 2. 发现的隐私漏洞（需要修）
- **家人卡泄露上门时间。** 家人卡二维码里是老人的账户 id。任何拍到这张卡的人，都可以在链上查这个 id 的 `Visited` 记录，知道老人家什么时候有人来、什么时候没人。对独居老人来说这是安全风险。
- **帮助记录可关联。** 每条 seal 都公开帮助者、受助者和时间。一旦某个 id 和真人对上，TA 的全部受助记录都被看光。时间银行里志愿帮助可以接受（用户知情同意），但作为长护险核验，可能触及医疗隐私法规（美国 HIPAA、欧盟 GDPR 中的健康数据），需要法律意见。

## 3. "为什么要用链"要说得更诚实
- 链的价值在**没有一方被所有人信任**的场景：跨城市、跨机构的时间银行；保险方和服务机构互相不信任的核验。
- 如果只有一家保险公司和一家机构，一个双方签名的普通数据库也能做到。所以不要说"只有链能做"，要说"多方之间需要一份谁也改不了的公共账本"。

## 4. 伦理：别把护工变成被监控的对象
- 英国家庭护理协会批评按分钟监控损害护理质量。如果我们只强调"抓骗保"，就是在加重对低收入护工的监控。
- 改为**双向保护**：凭证同样保护诚实的护工。韩国的追款判决说明，护工也需要证据证明自己确实去了。

## 5. 改进方向（按重要性排序）
1. **修隐私漏洞**：`Visited` 事件不再直接写老人 id，改成"盲化标签"：家人卡里存一个秘密值，事件只写 keccak(秘密, 随机数) 和随机数，守护人能认出来，外人对不上。
2. **证明两人在一起**（只能部分做到，要说清楚）：
   - 短时有效：一方屏幕显示的挑战码，只在 60 秒内有效，双方签名都必须包含它。拍照远程转发会更难，但仍然可能。
   - 位置指纹：双方手机各自提交位置哈希，必须一致。
   - 最强的方案是**带指纹的实体卡**：碰一下需要卡在场，指纹需要老人本人在场。这是路线图（成本和供货待核实）。
3. **上门全过程**：到门口 = 开始，双方确认 = 结束；申报时长不能超过实际在场时长；同一护工同一时间只能有一个进行中的上门。
4. **对合谋的回答**：链上记录让**事后抽查和异常检测**变便宜（比如同一护工一天在 5 个城市、某老人每天 8 小时服务），但不能防止合谋。这一点要在 Pitch 里如实说。
5. **商业版的隐私架构**（路线图）：长护险场景下，链上只存承诺（哈希）和签名验证结果，明细由经办机构保存。

## 6. 比赛策略
- 主赛道建议选 **Trust, Identity & AI Infrastructure**：官方点名 P256 / WebAuthn，而"上门真人核验"正是身份与信任问题。Consumer 赛道也可以，但时间银行在消费者层面的商业性较弱。
- 讲法：前台时间银行（情感、社会价值）+ 商业上门核验（收入）+ 诚实说明边界（防单方造假，不防合谋）。评委更容易相信诚实的团队。
